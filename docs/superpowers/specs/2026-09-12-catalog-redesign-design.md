# Редизайн каталога: главная и общий хром

Дата: 2026-09-12  
Репозиторий: `workevent-front`. Бэкенд и Filament в этом заходе не меняем.

Референс: макет светлой главной (hero, белый поиск, чипы отраслей, карточки с датой на фото, светлая подписка).

## Цель

Собрать макет на существующих компонентах. Главная получает новую композицию. Шапка, поиск, карточка события и подписка обновляются на всём сайте. Внутренние страницы (событие, календарь, блог, отрасль, город) по смыслу и блокам остаются как есть.

Новые сущности без аккаунтов: закладки и заявка «добавить событие» живут в `localStorage`.

## Вне объёма

- Логин, кабинет, серверные избранное и модерация заявок
- Отдельная страница «Избранное»
- Смена H1 / title / description главной в Filament
- Новые цветовые токены и смена шрифта
- Параметры вида и сортировки в URL
- Автотесты на визуал
- Перепись футера, страницы события, календаря и блога по содержимому

## Решения

| Тема | Решение |
| --- | --- |
| Объём | Главная + общий хром. Внутренние страницы не перекладываем |
| Сборка | Те же компоненты, новая вёрстка и поведение |
| H1 | Текст с `GET /v1/pages?path=/`, один видимый `h1`. Маркетинговый лид — не заголовок страницы |
| Журнал | Пункт меню ведёт на `/blog` |
| Подписка | Email + «Подписаться»; отрасли обязательны, контрол компактный |
| Закладки | `localStorage`, без отдельной страницы |
| Добавить событие | Публичная страница `/events/new`, заявка в `localStorage` |
| Вид и сортировка | Клиентское состояние уже загруженной выдачи, не в query |
| Поиск | Без поля отрасли; отрасль — чипы |

## Главная

Порядок блоков:

1. Глобальная шапка
2. Лид «Найдите событие, которое двигает вас вперёд.» и подзаголовок «Конференции, выставки и форумы для вашего профессионального роста» (не `h1`). Справа декоративный блок: текущий месяц и год в формате `СЕНТЯБРЬ '26`, без вымышленных названий событий
3. Поиск: название, город, даты, «Найти»
4. Чипы: «Все» + первые отрасли с `/v1/industries` (как сейчас, только с будущими событиями) + «Все отрасли» — поповер остальных, тот же фильтр на месте, не переход на `/events`
5. «Ближайшие события»: тулбар сетка/список и сортировка, затем текущий `EventsList` (те же `/v1/events`, `per_page` как сейчас у блока по отраслям)
6. Видимый H1 с бэка
7. Ссылки «Конференции в Москве» и календарь на SEO-год
8. Рекомендации (`is_priority`)
9. Пресеты — ссылки на `/events/[slug]`, как сейчас
10. FAQ и внутренняя перелинковка
11. Подписка из корневого лейаута
12. Футер без изменений по смыслу

Чипы — это нынешний фильтр `EventsByIndustry`, не второй каталог. Смена чипа пересобирает список через `industry_id` в клиенте, без перехода на `/events`.

Маркетинговый лид и подзаголовок — константы UI, не поля посадочной. Title, description и H1 по-прежнему только с бэка.

## Общий хром

### Шапка

Белая, липкая. Слева логотип и слово `workevent`. Центр: Мероприятия, Календарь, Журнал. Справа: иконка поиска на `/events` без query и кнопка «Добавить событие» на `/events/new`.

Мобильное меню — текущий бургер плюс поиск и «Добавить событие». URL пунктов не меняются, кроме подписи «Журнал» вместо «Блог».

### Поиск

Тот же `Search` и те же query: `query`, `city_id`, `date_from`, `date_to`. Поле отрасли удаляется. Оболочка — белая скруглённая полоса на главной и на `/events`. Пустой сабмит ведёт на `/events` без фильтров.

### Карточка

Один `EventCard` везде:

- сетка: фото 16:9, дата бейджем на снимке, город, название, отрасль, закладка
- список: миниатюра и те же поля в строку

Ссылка на событие не оборачивает кнопку закладки. Клик по иконке не открывает карточку события.

### Подписка

Тот же компонент в `layout.tsx`. Светлая полоса, поле email, кнопка «Подписаться». Выбор отраслей остаётся обязательным (`min(1)`), прячется в компактный контрол. `POST /api/subscribe` и цель `newsletter_subscribe` без изменений.

Кнопки и инпуты подтягиваем к макету за счёт текущих вариантов и `primary`. Палитру и `--radius` не расширяем.

## Закладки, вид, заявка

### Закладки

Ключ: `workevent:bookmarks`. Значение: JSON-массив числовых id.

Хук читает и пишет ключ, на той же вкладке карточки обновляются сразу. После reload состояние сохраняется. Отдельного пункта «Избранное» в шапке нет.

Нет доступа к `localStorage` — карточка живая, тост «не удалось сохранить на этом устройстве». Битый JSON сбрасываем в `[]`.

### Вид и сортировка

Тулбар только у «Ближайшие события» на главной и у каталога `/events`. В рекомендациях и в «похожих» на странице события тулбара нет.

Сортировка клиентская по уже загруженным карточкам: дата ближе (дефолт, как пришла выдача), дата позже, по названию. «Загрузить ещё» дописывает страницы как сейчас; сортировка применяется ко всему массиву на экране. В URL и API параметры не уходят — чтобы не плодить индексируемые варианты выдачи.

### Добавить событие

Статический сегмент `src/app/events/new/page.tsx`. В App Router он старше динамического `events/[preset]`, конфликт со слагом `new` не создаём.

Поля: название, даты, город текстом, отрасль из `/v1/industries`, сайт или email, короткий комментарий. Валидация на клиенте: название, хотя бы одна дата, контакт (сайт или email).

Успех: запись в `workevent:event-submissions` (массив заявок на устройстве), тост, очистка формы. Внешней отправки нет. Черновик не восстанавливаем. Повторные одинаковые заявки не дедуплицируем.

Страница, не модалка: корректны мобилка и «назад».

## Потоки данных

- Главная: как сейчас, параллельно `/v1/events`, `/v1/events?is_priority=true`, `/v1/industries`, `/v1/cities`, `/v1/pages?path=/`
- Поиск → `/events` с теми же query, что пишет текущая форма (минус `industry_id`)
- Чип отрасли → `EventsList` с `{ industry_id }` или `{}`
- Пресеты → `/events/[slug]`
- Закладки и заявки → только браузер
- Подписка → `POST /api/subscribe`

## Ошибки

- Пустая выдача каталога — текущий `EventsNotFound`
- Ошибка догрузки: список не затираем, кнопка «ещё» остаётся, тост «не удалось загрузить»
- Скелетоны в новой геометрии карточки
- Форма события: ошибки под полями, без сетевого запроса
- Подписка: тосты как сейчас; пустые отрасли блокируют отправку той же валидацией

## Проверка

В браузере, desktop и узкая мобилка:

1. Главная: лид, поиск, чипы, карточки, шапка, подписка
2. Поиск с городом и датами → `/events`, фильтры на месте, новая строка
3. Чип отрасли пересобирает список, «Все» возвращает общую выдачу
4. Сетка/список и сортировка не сбрасывают загруженные карточки; «ещё» дописывает вниз
5. Закладка на главной и в `/events` одно состояние; reload сохраняет; клик по иконке не открывает событие
6. `/events/new`: валидация, запись в `localStorage`, тост, пустая форма
7. Подписка с отраслью и без — прежнее поведение
8. Страница события и календарь: новые шапка и карточки, прежняя структура страницы
9. На главной один `h1`, текст с бэка; лид не в `h1`

Автотесты на этот заход не добавляем. Если понадобится регресс позже — точечно хук закладок и схема формы.

## Границы компонентов

| Единица | Делает | Вход | Зависимости |
| --- | --- | --- | --- |
| `Header` / меню | Навигация, поиск, CTA события | нет | маршруты `/events`, `/events/new`, `/blog`, календарь |
| `Search` | Фильтры название/город/даты | города; `industries` больше не принимает | `useRouter` → `/events` |
| `EventsByIndustry` | Чипы + тулбар + список на главной | события, meta, отрасли | `EventsList` |
| `EventsList` | Догрузка, опционально вид и сортировка | events, meta, params, флаг тулбара | `EventCard`, API |
| `EventCard` | Карточка сетки или строки | event, вид, флаг отрасли | хук закладок |
| хук закладок | Чтение/запись id | нет | `localStorage` |
| страница `/events/new` | Публичная заявка | отрасли | `localStorage` |
| `Subscribe` | Рассылка | отрасли | `/api/subscribe` |
